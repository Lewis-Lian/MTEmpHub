# 菜票中心使用指南

适用：2026-10-10 流程简化版本。月度发放和后续补扣保留两个页面；系统不调用外部充值或取款设备。

## 月度发放

1. 在“菜票中心 → 月度发放”选择**计划充值月份**。页面显示对应上月考勤，例如 2026-09 充值按 2026-08 考勤计算。
2. 点击“计算菜票”，核对人员、金额、异常、补扣及本月不发。考勤变更后可“重算草稿”，原补扣和本月不发选择保留，并查看金额变化。
3. 处理异常、核实来源并锁定考勤账套后“确认核算”。确认后调整应发只能到“后续补扣与对账”。合法退回草稿不解锁考勤；已有发放、已声明外部操作或后续考勤重算等情况不能退回。
4. 使用唯一“导出充值表（.xls）”入口下载两列充值表：员工编号、充值金额。工号保留前导零。**下载不登记到账**，请在菜票软件完成真实充值。
5. 已启用数据库核对时，点击“已完成充值，核对到账”；后续仍在同一入口“核对到账”。日期默认本充值月，跨月结束日期按需展开。未启用数据库时，按已确认凭证登记真实充值，账目自动刷新。
6. 结清后可查看金额摘要、展开核算明细，并从原入口再次下载。充值表按当前正差额导出，结清后可能为空，不是当初下载文件的归档副本；需保留首次下载文件及设备凭证。

## 后续补扣与逐人办理

在“菜票中心 → 后续补扣与对账”选择已确认月份。步骤条只显示进度，无需手动点“下一步”。

1. 人员表默认列出有差额或未完成任务的人员。搜索人员或勾选“显示全部人员”可给其他人追加调整。单人、批量登记选择“补发 / 扣除”，金额填正数并写原因；导入模板使用正数补发、负数扣除。批量登记和表格导入只改变应发，不操作设备。
2. 首次建立可靠基线后，保存调整自动更新未操作清单。当前任务卡显示工号、姓名、方向及正数两位金额。复制工号如 `001`，复制金额如 `24.00`；只有复制成功才显示“已复制”，失败请重试。
3. 在菜票软件按当前工号办理充值或取款。可“暂时跳过”留到队尾；名单只切换当前任务。点击“已完成充值/取款，下一人”保存**外部操作声明**，不会创建到账、扣回或清零流水，不改变净已发。
4. 当前任务、跳过顺序和已操作状态由服务器保存。刷新或切换月份后可继续；同一人两个方向计为两“项”，不是两个人。
5. 已操作项进入待核对。数据库核对在原入口执行；未启用数据库时，在“实际流水核对”登记相应任务的真实充值/扣回。金额不得超过该任务方向的剩余金额。普通无任务登记仍受净差额限制。
6. 多任务、多笔同额或超额候选不能唯一匹配时，在“实际流水核对”逐笔确认关联并核实金额、人员、方向、来源和日期。已有流水只分配可用金额，不重复记账。历史流水早于任务基线或创建时间不能自动核销新任务。

人员“明细”集中查看补扣、实际流水、原因、操作人及合法冲正。后续页没有充值表下载或批量设备办理入口。

## 抵消设置与算例

管理员在“系统设置 → 项目更多设置”修改“补发与扣款抵消”，默认开启、立即保存。后续页仅显示清单采用的方式。

已结清 176 元后，新增补发 40、扣除 16：

| 方式 | 办理任务 | 实际结果 |
| --- | --- | --- |
| 开启 | 充值 24 | 应发 200，实际充值后净已发 200 |
| 关闭 | 充值 40、取款 16 | 先充后取：净已发 216 → 200；先取后充：160 → 200 |

补发 24、扣除 24：开启时无需办理；关闭时仍有两个 24 元任务，净差额零不代表任务完成。

清单冻结金额和抵消快照。设置变化后按提示刷新操作清单，只重建尚未操作项；待核对、部分到账及已匹配金额保留，不重新抵消或重发。另一个管理员或页面修改后，旧版本提交会被拒绝，请重新读取并核实，不反复提交旧卡片。

## 部分到账、延迟与更正

- 24 元任务实际到账 10 元，显示已匹配 10、剩余 14。刷新、设置切换不会把已到账 10 再生成待办。
- 没查到流水可能是延迟。先核实设备与凭证；不要直接再次充值/取款。确实尚未到账时，选择“确认尚未到账，重新办理”，填写原因，仅办理剩余金额。
- 没发生真实操作时可撤销操作标记；撤销不删除或冲正真实资金。已有资金只能按合法业务更正处理；冲正后任务恢复对应剩余义务，历史保留。
- 核对失败保留原账和待核对进度，在同一入口重试。手工和数据库来源不能重复混用；数据库来源资金不允许手工重复登记或冲正。
- 取款需人工分类为业务扣回或月末清零。清零不核销补扣任务；完成分类后在唯一核对入口继续。

## 旧月份首次接入

1. 先选旧充值月，核对全部历史实际充值、扣回、冲正和清零分类，收集设备凭证。数据库核对未启用时仅登记已证实的真实流水，不用操作声明代替。
2. 提示需核对基线时，不要把全量历史补扣再办一遍。历史哪些已办理无法确定时，暂停生成分开方向任务，先核实。
3. 打开“确认旧月剩余基线”。默认只提供已证实净差额对应的方向金额；需要分开办理时，逐人填写核实后的待充值、待取款及说明，两方向净额必须与当前差额一致。
4. 确认使用当前页面所见的版本。若冲突，使用只读重新读取入口，重新核实金额及依据后确认，不套用失效确认内容。
5. 建立基线后只办理剩余义务；历史已支付调整不会重新全部入队。旧数据的空任务列表不代表已结清。

## 备份与恢复

使用包含“菜票核算与充值”分类的新版多月份 V2 备份，保存任务、真实分配、基线、当前定位、跳过顺序和历史抵消快照。按人员及业务 key 引用，可恢复到本地数据库 ID 不同的安装。

恢复先预览依赖和资金一致性。缺父任务、人员或资金、超额分配、已冲正资金或不一致任务状态会阻止确认。恢复只还原本地记录，不调用设备，不把待核对或部分到账改为待重办；恢复后先核实实际流水。

旧 V1 和缺新数据集的旧 V2 将该范围视为 **absent（未包含）**，不视为完整空表，不删除目标已有任务、分配或定位。旧格式不携带新任务；需要可移植保存完整进度时使用新版 V2。

抵消开关是安装级设置，不随月度备份覆盖；目标安装保留自己的开关，恢复业务清单沿用历史快照。切换历史清单必须走正常刷新规则。
