# 菜票查询、台账扩展与下载中心方案

日期：2026-10-08。状态：用户已授权实施，采用建议口径；本文件保留设计依据，实施与验收见同目录实施计划。

## 1. 目标与已确认边界

将菜票查询、业务登记和报表存档分别放在查询中心、菜票中心和下载中心，使日常查询、操作和归档各有明确位置。

已确认：

- 菜票查询放在查询中心，独立于员工考勤、管理人员考勤。
- 菜票中心不增加“查看查询报表”入口。
- 原有汇总下载与菜票存档下载统一到独立下载中心。
- 部门月度登记、外来人员领用、全年汇总、月末取款是四个独立功能。
- 外来人员菜票领用分为充卡、纸质两类。
- 月末未用余额在现有菜票软件中清零，本系统只记录或读取处理结果。
- 取款记录中卡余额等于清零取款金额，只保存一个业务金额，不要求重复录入。
- 沿用现有菜票核算规则：最终实际打卡天数 × 8 元，加额外补扣。参考表中的天数取整、异常刷卡扣款公式不自动成为新规则。

## 2. 导航与页面安排

| 中心 | 页面 | 职责 |
| --- | --- | --- |
| 查询中心 | 原有考勤查询页面 | 保留现有查询功能 |
| 查询中心 | 菜票查询 | 只读查看人员菜票核算、补扣、到账与差额 |
| 菜票中心 | 月度发放、后续补扣与对账、历史台账 | 复用现有流程 |
| 菜票中心 | 部门菜票登记 | 月度部门金额汇总、登记人和备注 |
| 菜票中心 | 外来人员领用 | 充卡、纸质发放的独立台账 |
| 菜票中心 | 全年菜票汇总 | 年度充值、领用、消费与收回统计 |
| 菜票中心 | 月末取款记录 | 保存外部已完成的余额清零记录 |
| 下载中心 | 考勤报表 | 承接原有汇总下载页面 |
| 下载中心 | 菜票报表 | 按参考表结构生成存档 Excel |

下载中心采用两个页面或页签，不新建独立下载任务系统。原有考勤下载先迁移导航和页面归属，复用筛选、报表选项与后端生成逻辑。原 `/employee/summary-download` 地址保持兼容并转到新页面，已有链接可继续使用。

现有充值系统使用的专用充值文件仍保留在月度发放步骤中，存档报表不代替该操作文件。

## 3. 菜票查询

- 默认按计划充值月份查询，同时显示对应考勤月份。
- 筛选项：月份、部门、人员、员工/管理人员、核算状态及结清状态。
- 人员字段：工号、姓名、核算部门、人员类型、实际打卡天数、基础金额、额外补扣、应发金额、净已发金额、差额、本月不发说明。
- 明细展示补扣原因、发放记录及核算依据，复用现有数据，不另建查询账。
- 员工与管理人员可以在同一菜票页面中筛选，但不混入两个考勤查询页面。
- 清零取款在详情中单独列示，不减入“净已发金额”或产生“待补发”差额。
- 未生成核算时显示无核算数据，不把不存在的月份显示为零；草稿须明确标识。

四项新台账各有独立页面。本阶段不再建设一个汇集所有台账的查询大屏。

## 4. 四项台账功能

### 4.1 部门菜票登记

按充值月份和人员核算时保存的部门归属汇总，员工、管理人员均纳入，保留参考表的部门、金额、登记人、备注。

同时显示“应发合计”和“实际发放合计”；本轮存档表的“金额”采用实际发放合计。管理员补充登记人和备注，不手工重复录入自动汇总金额。

部门登记是人员金额的汇总视图，不再产生一笔发放流水。额外补扣影响应发合计，实际补发或纠错扣回影响实际发放合计；月末余额清零不回改本月发放额。外来人员领用保持单独台账，不混入员工部门金额。

历史部门原账继续保留原值，允许与人员原账或正式核算对照，不覆盖成当前汇总值。

### 4.2 外来人员菜票领用

记录月份、日期、填表人、归属部门、外来单位/人员、姓名、服务时间或期间、天数、发放金额、类别、卡号、备注。

- 类别明确为充卡或纸质；纸质领用不要求卡号。
- 外来人员不必存在于员工档案中，不自动创建员工或生成考勤补贴。
- 金额独立登记，不强制按天数 × 8 元计算。
- 按月、部门和类别汇总，充卡与纸质分别展示。
- 记录实际发放事实，保留录入人和时间；错误记录作废或更正并保留历史。

### 4.3 全年菜票汇总

按自然年列出 1—12 月，月份采用实际业务发生月份；与“考勤月→次月计划充值”的核算时间分别标识。

| 指标 | 建议来源与口径 |
| --- | --- |
| 员工及管理人员实际充值 | 已登记或核对的实际充值；纠错扣回、冲正按实际日期反映净额 |
| 外来人员充卡 | 已登记的充卡领用金额 |
| 纸质领用 | 已登记的纸质领用金额，单列 |
| 二楼、三楼消费 | 先支持按月录入；验证数据库字段及范围后再接只读数据 |
| 消费金额 | 二楼消费 + 三楼消费 |
| 收回金额 | 已完成月末清零取款记录合计 |

建议“充值金额”包含员工/管理人员实际充值与外来人员充卡，纸质领用单列。只有确认消费范围也包含纸质后，才计算包含纸质的发放与消费比较值。页面可展示更细来源，参考格式的存档文件保持约定列顺序。

“收回金额”取实际取款记录，不采用参考表的“充值 − 消费”直接替代。充值、消费和收回存在期间差异，不承诺三者天然相等，也不据此推算个人余额。

没有录入或读取的消费月份显示“未录入”，不能默认为零。年度合计同时说明数据覆盖月份。

### 4.4 月末取款记录

取款在现有软件中办理。系统记录业务月份、实际处理日期、人员编号、姓名、部门、卡号（可为空）、清零取款金额、备注、来源和录入人。

- 金额表示当时未使用并已清零收回的余额，一项金额即可。
- 支持员工、管理人员及客人卡；未关联员工的记录仍保留。
- 不执行取款指令，不修改外部卡余额，不根据考勤推算余额。
- 手工登记和 Excel 导入先落地；数据库只读接入须有明确的已完成取款流水与分类依据。
- 查询、月度导出及年度收回汇总使用同一组有效记录。

现有数据库对账将 `ST_TakeFund` 取款统一用于核算扣回。扩展时必须区分“发放纠错扣回”和“月末余额清零”。同一外部流水只能归属一种业务，重复读取、导入不得重复计入。不能仅凭月底日期、卡号或金额自动分类；预览后确认归属。无法确认的流水保持待分类，不进入结清和年度收回。

例如：应发 176 元，已充值 176 元，消费后剩余 20 元在月底清零。发放仍结清，月末取款记 20 元，年度收回增加 20 元，不产生待补发 20 元。

## 5. 下载中心与存档格式

统一入口、筛选和下载反馈，但各报表保留各自月份含义与人员范围，不强制所有报表共用考勤账套月份。

| 报表 | 下载内容 | 期间 |
| --- | --- | --- |
| 考勤汇总 | 复用原有多工作表导出 | 考勤账套月份 |
| 月度充值记录 | 员工异常查询、员工充值记录、管理人员查询 | 计划充值月，标明对应考勤月 |
| 部门菜票登记 | 部门、金额、登记人、备注及合计 | 充值月；年度文件可按月分工作表 |
| 外来人员领用 | 明细、充卡/纸质分类汇总 | 所选月份或全年 |
| 全年菜票汇总 | 1—12 月充值、消费、楼层消费、收回及全年合计 | 自然年 |
| 月末取款明细 | 按月保存人员、卡号、部门、清零金额、备注 | 业务月份及处理日期 |

分别下载五类菜票报表，不强制合并成一个大工作簿。保留参考表的字段顺序、标题、汇总和打印布局；月度充值记录不再重复附上右侧部门透视汇总。

存档采用导出时的有效结果值，金额使用数值单元格，不依赖 XLOOKUP 缓存。异常次数只作依据展示，不自动扣钱；旧模板的“实际充值金额”须明确映射实际发放结果，不将应发伪装成已到账。旧表中不再参与计算的字段需在字段映射评审中明确是否保留，不能填入误导性的扣款金额。

文件标明期间、数据状态和导出时间。草稿可下载但明确标注，正式月度存档以已确认核算为依据；导出不会自动确认、登记发放或执行清零。后来补扣或更正反映在重新导出的文件中，已下载文件作为当时存档保留。本阶段不新增服务器端版本化归档仓库。

## 6. 历史表格导入

复用“上传→预览→映射→确认”流程，分别识别部门登记、外来人员领用、年度月度统计和取款记录。

- 导入保留来源文件、工作表及行号，排除右侧透视表、总计行和空白行。
- 原表部门名字与当前部门不一致时提供映射，保留原名。
- 工号和卡号按文本保存；未匹配员工或客人卡允许保留。
- 取款表“卡余额”和“取款金额”按用户确认的同一金额口径映射。
- 原表年度总额只作对账，不能再加到明细合计中。手工年度原账与系统汇总不直接叠加。
- 同文件重复导入拦截；跨文件或数据库重复的疑似记录展示核对，不用姓名、日期和金额简单去重而误删真实记录。
- 原始充值文件、年度登记文件及取款文件保持独立，不修改用户附件。

参考文件存在年份冲突：外来人员页名称为 2026 年但标题写 2025 年，取款文件也含明确标注 2025 年的工作表。导入时逐页确认年份及业务月份，不能按文件名全部归为 2026 年。

## 7. 数据、权限与兼容

复用现有核算批次、人员明细、补扣、实际发放和历史导入数据。最少新增以下持久化数据：

- 部门月度登记信息：月份、部门关联或快照、登记人、备注；金额从同一人员集合派生。
- 外来人员领用记录：领用事实、类别、金额、来源及更正历史。
- 月末清零记录：人员/卡号快照、日期、金额、来源及更正历史。
- 月度消费统计：年份月份、楼层金额、来源及更正历史。

年度统计通过上述数据生成，不另建可重复累加的年度总额账。金额沿用整数分与 Decimal 规则。确认后的历史人员、部门快照不随主数据变化。

清零记录及外来领用按实际业务月份归档，不强制挂在考勤账套上。新增独立台账须纳入整库备份和切库迁移；按月备份的范围在实现前明确为业务月并展示给操作者，避免遗漏与考勤月无关的记录。

权限建议：

- 考勤下载继续沿用 `summary_download` 权限。
- 菜票人员查询和对应导出沿用 `meal_ticket_query` 及现有人员/部门范围。
- 菜票中心新增台账默认管理员维护。
- 外来领用、全年汇总和取款报表建议使用独立查看/下载权限；默认仅管理员。全年全部金额不得通过人员查询权限直接暴露。
- 下载中心按用户可下载内容展示入口，后端执行同样的检查。
- 受限账号的部门汇总只能汇总可见人员，不展示全部门隐藏金额。

现有数据和旧对账结果不自动重新分类。若已将月末清零记作核算扣回，须先预览影响，再明确更正方式；新方案不能静默回改资金历史。

## 8. 实施顺序及验收

1. 导航与菜票查询：迁移考勤下载入口，新增独立菜票只读页面。验收原有下载参数、权限、旧链接仍可用，员工/管理人员考勤页面不混入菜票功能。
2. 部门登记与月度存档：复用现有核算和实际发放。验收部门合计与对应人员金额一致，登记不新增发放，导出不包含重复部门透视汇总。
3. 外来领用与月末取款：新增独立台账及导入。验收充卡/纸质可分别查询，客人卡可记录，20 元清零不会让已结清发放变成待补发，重复来源不重复入账。
4. 全年汇总及剩余存档报表：接入业务台账、消费录入和年度下载。验收月度与全年合计可追溯，无消费数据不显示零，收回取实际清零记录。
5. 兼容验证：检查权限、跨年、年份映射、备份恢复、SQLite/MySQL 增量迁移及 Excel 数值、工作表和打印布局。

实施时针对金额分类、权限、重复导入与跨年写回归测试；下载布局用真实参考表比对字段及渲染，不用只检查文件生成成功代替验收。

## 9. 评审时需要确定的口径

用户授权先实施、后续调整。本轮采用以下建议口径，保留为后续评审依据：

1. 部门登记表“金额”是否采用实际发放合计（建议），而不是应发合计。
2. 年度“充值金额”是否包含外来人员充卡；纸质领用建议单列，需确认消费数据是否涵盖纸质。
3. 二楼、三楼消费首期是否按月手工录入；数据库自动读取需进一步核对来源。
4. 存档充值表是否保留旧的异常扣款和充值天数列；保留时需标明当前用途，不复用旧公式。
5. 月末清零首期是否采用手工登记与 Excel 导入，后续再增加有分类确认的数据库读取。

实施计划见 `2026-10-08-meal-ticket-query-download-plan.md`。历史附件不自动导入运行数据库，部署升级由实际运行环境执行。
