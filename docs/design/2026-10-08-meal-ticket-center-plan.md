# 菜票中心实施计划

规格：2026-10-08-meal-ticket-center-spec.md。执行：本会话逐项实施；用户已授权实施，不重复请求开始确认。

## 全局约束

严格复用打卡字段最终值 × 8 元；考勤月次月充值；保留补扣；人员去重；部门自动汇总；冻结确认账；管理员写入、查询账号范围授权；SQLite/MySQL 兼容。

## 任务

1. 数据模型与核算服务 → 以真实 SQLite 数据测试月度覆盖、管理人员字段、月份转换、草稿重算与冻结。
2. 补扣、充值与 API → 测试 22 天加 16 元、部分发放、扣回、冲正、并发版本和重复请求；读写授权与导出。
3. 历史导入 → 测试公式缓存、空页、重复人员、工号/部门映射、月份选择、预览确认和部门对账。
4. 前端与导航 → 页面测试核算、调整、确认、充值和导入；构建与既有前端测试。
5. 迁移、备份与删除关联 → 测试切库表清单、初始化、账套备份恢复和删除保护。
6. 完整回归及独立代码审查 → 修复实质问题后报告验证结果。

## 接口约定

后端 /api/meal-tickets：按 recharge_month 查询月度批次；generate、confirm、adjustments、payments 写入传 batch.version；export 下载 xlsx；imports 上传预览与确认。
金额对外以元显示，对内整数分；API 错误返回 error 与明确 HTTP 状态。前端三个路由共用模块页面，以核算/充值/历史区分视图。

## Review Focus

- 从实际出勤天数误取菜票天数。
- 源字段发生变化后旧草稿仍可确认。
- 并发充值或冲正超过应发/重复扣回。
- 历史部门汇总被再次计入发放金额。
- 范围受限账号通过详情或导出访问全月数据。

## 验证方式

先添加 tests/test_meal_tickets.py，观察新接口/模块缺失失败，再开发对应实现并运行；前端同样先添加页面行为测试。运行 pytest、vitest、tsc/Vite build 和 git diff --check。实施进展与取舍记录于该计划对应的 progress.md。
