# 菜票数据库到账核对

考勤与菜票共用“数据来源与同步”中保存的 SQL Server 连接。员工考勤来源仍由原有选择控制；菜票核对有独立开关，默认关闭，开启不改变考勤来源或连接密码。

确认核算后，在“核对结清”区域点击“读取数据库并核对”。系统只读查询菜票数据库，将实际流水登记到本地菜票账，自动更新净已发金额、差额和人员结清状态。

| 业务操作 | 数据库来源 | 实际金额 |
| --- | --- | --- |
| 首次补贴发放 | ST_Subsidy、ST_SubsidyHistory | Subsidy_Fund |
| 后续补发充值 | ST_SupplyFund、ST_SupplyFundHistory | Supply_Fund |
| 取款扣回 | ST_TakeFund、ST_TakeFundHistory | Take_Fund，记为负数 |

通过 ST_Person.Person_No 精确匹配核算时保存的员工编号，包括前导零与离职人员。Plan_Fund、XF_Subsidy 下发队列和卡余额不作为实际到账金额；零金额流水不计入。

核对范围默认所选充值月的第一天至最后一天，结束日期包含全天。跨月补发或取款可选择实际处理的日期，已登记的原月流水继续保留。其他月份的补贴发放不会计入。充值和取款流水没有本地核算批次标识，管理员应选择属于本批次的实际处理日期，避免将另一月份的补发或取款纳入；已计入其他月份的同一流水会被拦截。

核对按共享数据库身份、流水类型和流水编号去重，当前表与历史表的相同流水只记一次。重复点击不会重复发放或新增记录。多发不截断金额，显示为待扣回。读取失败、版本变化、已登记流水修改或缺失、连接切换及流水编号冲突均不提交本次核对。

未启用数据库核对且没有数据库流水的账目保留手工登记。已有手工登记的月份暂不自动合并，避免重复计算。已有数据库流水的账目禁止再手工登记或冲正，关闭开关只暂停核对，重新开启后继续读取实际流水。实际充值和取款仍在菜票软件中办理。

本地发放流水及去重标识沿用原有备份/恢复结构，不新增数据库表或字段。本次核对摘要展示当前操作的时间、范围、三类流水数量、新增/已登记数和未匹配/零金额数量；刷新后保留发放明细，摘要需再次核对获得。
