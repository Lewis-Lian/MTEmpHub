# 多月份备份与选择性恢复使用说明

适用于阶段 0–9 已实现的界面和 `/api/admin/backups/` 接口。管理员入口：**账套中心 → 账套管理 → 账套设置 → 账套导入与导出**。

## 1. 导出备份

1. 点击“导出 YYYY-MM 账套”（没有选中账套时显示“导出月度账套”），打开“导出多月份备份”。按钮上的月份只是初始选择，可以再勾选多个甚至跨年的月份。
2. 核对“选择导出月份”和“导出内容（默认全部）”。全部 11 类默认选中，可按需要取消。
3. 点击“开始导出”，等待实际收集、打包、校验及下载进度；显示“备份下载完成”后保管 ZIP。导出过程中不能重复启动。

| 界面类别 | 资料范围 |
| --- | --- |
| 账套参数与厂休 | 所选月份参数、厂休明细 |
| 考勤数据 | 日报、月报、逐日/月度修正、修正历史、同步历史及月度资料快照 |
| 菜票核算与充值 | 核算、明细、补扣、充值/扣回/冲正及历史导入 |
| 菜票独立台账 | 所选业务月份独立台账及来源信息 |
| 原始文件 | 所选业务依赖的归档文件 |
| 当前部门资料 | 完整部门树和有效状态，包括空部门 |
| 当前员工资料 | 完整人员、状态、卡号及统计来源，包括所选月无业务人员 |
| 班次与默认分配 | 完整班次及人员默认分配，包括未分配班次 |
| 账号、密码与权限 | 密码哈希、有效/禁用状态、角色、页面权限、人员和部门授权及头像 |
| 跨月请假与加班 | 与所选月份重叠的单据，按业务键去重 |
| 年度统计与年假 | 涉及年份的年假余额和管理人员年度统计及来源 |

当前资料也保留归档状态。包内不含明文密码、连接凭证、`.env`、JWT 密钥或消息。ZIP 本身不加密；包含账号哈希和业务资料，应限制访问并妥善保存。

取消“原始文件”时，依赖原文件的记录不会被偷偷补入。若所选文件缺失，导出报错，需核对归档或调整范围。上传 ZIP 不能超过 **100 MiB**，单成员最多 100 MiB、解压总量最多 500 MiB、成员最多 10,000 个；超限请减少月份或内容，不支持分卷。

## 2. 上传与选择范围

1. 点击“导入月度账套”，拖入一个 ZIP 或点击“选择账套备份”。支持 v1 单月旧包和 v2 多月包，不支持更高的未知版本。
2. 在“核对差异”查看“识别到的月份”“实际包含的类别”和“备份覆盖范围与完整性”。初始只选择实际包含的类别；未包含类别不可勾选。
3. 如只恢复某个月考勤，取消其他月份及类别，再点击“重新预览”。未选月及类别不能隐式改变。
4. 跨月/年度记录需要逐条勾选“恢复条目”，查看实际影响月份。只勾选“跨月请假与加班”或“年度统计与年假”不会选中其中记录。

跨月/年度条目使用服务端给出的逐行标识（row_key）；不要自行拼接标识或只凭大类别提交。年度记录可能影响整年，跨月充值也可能影响源考勤月以外的月份。任何实际影响月被锁定时须先明确解锁，再比较。

| 覆盖状态 | 按备份缺失移除系统记录 |
| --- | --- |
| 已包含、完整且已选 | 允许；明确空且完整的范围也可能移除全部对应记录 |
| 未包含（absent） | 不允许；缺少内容不代表空集合 |
| 不完整（incomplete） | 不允许；目标未覆盖记录保留 |
| 未选月份、类别或跨月/年度条目 | 不执行 |

v1 的共享资料是关联子集，缺少账号和完整历史快照；不会按缺失删除其他当前资料。旧包缺少新增类别也按 absent 处理，不能当完整空集合。v2 同样以实际 included/complete 声明为准，不能只看版本号认定完整。

## 3. 核对差异与批量处理

| 差异状态 | 默认处理 |
| --- | --- |
| 备份新增 | 采用备份新增 |
| 值不一致 | 采用备份更新 |
| 系统独有 | 仅在完整、已包含、已选范围内按备份移除；其他范围保留系统 |
| 一致 | 保留系统，无实际变更 |

展开“查看字段差异”查看系统值、备份值及数值差额。账号密码只显示“一致/不同”，不会展示哈希。

可以按月份、类别、差异状态、编号或姓名筛选，勾选任意行，再点击“所选行采用备份”“所选行保留系统”“所选行跳过”。“勾选筛选结果（N 条）”作用于全部匹配且可操作的行，不只当前显示的 100 行；“显示更多差异”逐批展示差异。隐藏的已勾选行有数量提示。

**批量勾选与采用方式是两件事**：取消勾选只取消批量操作目标，不会撤销已设置的采用方式。想保留某条系统独有记录，需明确改成“保留系统”或“跳过”；仅取消批量勾选不会取消默认移除。对于备份新增行，可选“不新增”或“跳过”。

资料依赖提示会列出所需记录，例如人员所属部门、上级部门、默认班次、账号授权、月度快照、归档文件或菜票资金/冲正关系。请明确补选所需记录、保留已有依赖，或缩小恢复选择，再重新比较。系统不自动补依赖、不越过选择范围。菜票完整且资金关系一致时可覆盖冲突；留下悬空冲正或混合不一致核算历史会被阻止。

## 4. 历史资料与快照质量

月度业务携带独立的历史资料快照；当前转部门、离职、班次或来源设置变化，不自动刷新过去月份。界面显示系统与备份质量，并展示快照来源：

- **来源可证（verified）**：资料有可核对的来源。
- **旧数据基线（baseline）**：保证形成后历史稳定，不能证明当时真实资料。
- **资料不完整（partial）**：存在未补齐或未证实部分，需结合来源核对。
- **缺少快照（missing）**：旧月份尚未形成所需历史身份，不能宣称已隔离。

恢复保留备份的来源和质量。共享资料变化若会改变未隔离旧月，或快照变化会影响未选类别，比较会阻止恢复；不要用自动采集当前值或扩展范围来绕过。旧月资料需管理员先只读核对，再按明确月份、证据另行采集或修正。

## 5. 确认恢复与结果

点击“查看导入确认”，核对恢复月份、类别、新增、更新、退出当前资料、删除业务记录及跨月/年度影响。阻止原因未解决时不能执行“确认导入”。

“退出当前资料”适用于员工、部门、班次、账号：保留本地 ID 和历史引用，退出有效集合；人员离职业务状态与此不同。业务记录移除才是实际删除。恢复使用业务编号映射目标本地 ID，不照搬源库 ID；最终必须保留至少一个可登录管理员。

确认后系统再检查目标指纹、依赖和锁定范围，全部所选月份、账号及数据库写入在同一事务完成。归档新文件先暂存；失败保留目标原文件，成功仅清理已无引用旧文件。**菜票仅写本地记录，不调用设备，不重放充值或扣款。**

成功先显示“账套恢复完成”、月份、计数和警告（warnings）。先核对并保存结果；文件清理或缓存刷新警告不表示数据库恢复失败。若提示“本次恢复更新了您的账号或权限，请核对结果后重新登录”，结果会先保留，不立即加载业务；点击“重新登录”或关闭结果后进入登录页，使用恢复后的密码。受影响账号的旧登录失效。

## 6. 失败与重试

- **目标数据已变化（409）**：选择保留，但确认失效；点击“重新预览”，核对新差异后再确认。
- **数据或新文件写入失败**：整次业务回滚；范围、勾选、采用方式保留，可调整并重新比较后重试。
- **缺依赖、锁定月份、管理员或历史隔离阻止**：按具体提示解决，不强行确认。
- **任务过期、他人任务、已完成任务**：拒绝执行。预览有效期 1 小时，仅上传管理员可用；过期请重新上传，已成功任务不可重复确认。
- **ZIP 超限、损坏、路径或校验失败**：导入停止，重新取得有效备份，不修改包校验声明来强行导入。

预览本身不写业务数据。恢复成功不代表已核实真实过去，也不等于整站灾难恢复；完整运维备份仍需数据库、上传目录和配置。

## 7. 验证与运维交接

实际命令、十个设计验收场景证据和环境限制见 [阶段 10 执行记录](design/2026-10-09-monthly-backup-plan.md#实际执行记录阶段-10)。已完成合成 SQLite、隔离 MySQL 8.0.46、独立连接并发锁及隔离真实浏览器恢复验证；另验 24 月、67,200 条考勤和 90 MiB 文件。前端组件 HTTP 模拟不等于浏览器验收，这些限定验证也不等于生产签收；目标环境文件权限/磁盘、多主机、更高并发及浏览器大列表/网络性能仍需继续验证。复跑方法见 [隔离验收说明](testing/monthly-backup-verification.md)。

生产数据库升级或部署须另获授权。现有库升级到唯一 head `20261009_account_state`，新空库用 `init-db` 建表并记录版本，先建立可登录管理员再通过界面恢复；不要对无表空库直接执行 `db upgrade`。整库切换清单仍遗漏四张既有表，不要把该向导当作完整备份搬迁。
